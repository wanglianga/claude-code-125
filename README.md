# 校园校服订购尺码试穿与售后换码平台

基于 **Next.js 14（App Router）+ MySQL 8** 的全栈平台，覆盖校服业务全流程：

> 订购计划 → 体型信息采集 → 试穿日尺码录入 → 家长确认订单/缴费 → 生产批次 → 供应商分批发货 → 分批发放/补领签收 → 换码/补发/退款/投诉售后 → 供应商考核

六类角色围绕**同一名学生、同一批校服**协作：学校总务、班主任、家长、供应商、工厂、售后客服。

## 功能清单

| 模块 | 说明 |
| --- | --- |
| 订购计划 | 按校区/年级/班级维护计划，项目含季节套装、运动服、礼服、增购件；支持多校区统一采购、毕业班补订 |
| 体型信息 | 家长填写身高体重、常穿尺码、特殊版型需求 |
| 试穿管理 | 班主任按时段组织试穿，录入上衣/裤子/裙装/外套/鞋码建议并自动通知家长 |
| 订单缴费 | 家长按试穿建议确认订单（可改尺码、选增购件），模拟在线缴费；贫困生自动减免；迟缴费自动标记 |
| 生产批次 | 总务将"已确认且已缴费"订单打包成批次下达供应商；供应商可看到哪些订单**不能投产**（未缴费/未确认） |
| 分批发货 | 供应商对批次内订单分多批发货，工厂更新生产进度与预计到校时间 |
| 分批发放 | 总务/班主任按班级分时段发放，现场签收登记；未领取自动转入**补领专场**，缓解发放拥堵 |
| 售后换码 | 换码、补发、退款、投诉、面料过敏、错领调换、漏发补发七类工单；客服受理/办结/驳回，退款自动登记流水，换码自动更新订单尺码 |
| 异常处理 | 学生转学自动取消订单并退款；工厂漏发、班级错领、成长过快换码等场景均有工单流转 |
| 供应商考核 | 质量/交期/服务三维评分，供应商可见 |
| 进度看板 | 学校按班级/学生查看缴费、试穿、生产、发放、换码、售后进度；订单 360° 时间线留痕 |
| 通知中心 | 关键节点自动通知相关角色（试穿、缴费、催缴、到货、发放、售后进度） |

## 一键启动（Docker Compose，推荐）

```bash
docker compose up --build
```

- 应用：http://localhost:3000
- 首次启动自动建表并写入演示数据（MySQL 数据持久化在 `mysql_data` 卷）
- 重置数据：`docker compose down -v && docker compose up --build`

## 本地开发

前置：Node.js ≥ 18，本地或远端 MySQL 8（MariaDB 10.5+ 亦可）。

```bash
# 1. 安装依赖
npm install

# 2. 配置数据库连接（默认值如下，可按需修改）
export DB_HOST=127.0.0.1 DB_PORT=3306 DB_USER=root DB_PASSWORD=你的密码 DB_NAME=uniform

# 3. 初始化表结构与演示数据（空库才会写种子数据，可重复执行）
npm run init-db

# 4. 启动
npm run dev        # 开发模式，http://localhost:3000
# 或：npm run build && npm start   # 生产模式
```

## 验证方式（以下均为实际执行过的验证）

交付前已在 **Node 22 + MariaDB 10.11（MySQL 协议）** 环境下完成 `npm run build` 并对生产构建产物（`.next/standalone`，与 Docker 镜像内运行方式一致）执行过两轮自动化验证，全部通过：

```bash
# 先启动应用（见上文），再执行：
node scripts/smoke.js       # 41 项：六角色登录、越权拦截、24 个页面关键内容渲染
node scripts/flow-test.js   # 27 项：真实提交表单走通核心业务流（会改写演示数据；
                            #       恢复方法：清空数据库后重新执行 npm run init-db，
                            #       或 docker compose down -v 后重新 up）
```

`flow-test.js` 覆盖的业务闭环：家长缴费（逾期自动记迟缴费）→ 客服受理并办结换码工单（订单尺码自动更新、事件留痕）→ 供应商分批发货/确认到校（批次自动转"已到校"）→ 总务打包已缴费订单生成新生产批次 → 家长提交漏发补发工单 → 班主任创建分批发放场次（自动带出可发放学生）。

手工验证建议路径：

1. **家长流程**：`parent3` 登录 → 我的孩子 → 王一鸣 → 保存体型信息 → 确认订单 → 立即缴费（逾期会标记"迟缴费"）。
2. **供应商视角**：`supplier1` 登录 → 工作台可见"未缴费不能投产"清单 → 批次 `B2026-0001` → 勾选订单创建发货单 → 确认发货 → 确认到校。
3. **工厂视角**：`factory1` 登录 → 将批次更新为"生产完成"并填写预计到校时间。
4. **发放签收**：`wang` 登录 → 发放管理 → 创建分批发放场次 → 现场登记签收/未到 → 未领学生创建补领专场。
5. **售后闭环**：`parent1` 提交换码申请 → `service1` 受理并办结（填新尺码）→ 订单明细尺码自动更新，家长收到通知。
6. **总务看板**：`admin` → 订购计划 → 班级进度汇总/学生进度明细/投产就绪；基础数据中办理"转学"会自动取消订单并退款。

## 技术说明

- 服务端渲染 + Server Actions，无前端状态库；会话为 httpOnly JWT Cookie（`jose`），密码 bcrypt 加密
- 关键写操作均在数据库事务内完成，并写入 `events`（时间线）与 `notifications`（通知）
- 项目类型为全栈（含完整前端页面），不提供 Swagger/OpenAPI
- 目录结构：`src/app`（页面与 API）、`src/lib`（db/session/queries/actions）、`src/lib/schema.sql`、`src/lib/seed.sql`、`scripts/init-db.js`
